# 인앱 브라우저 vs 웹뷰 vs Linking.openURL

## 1. Linking.openURL

- **설명:**
  - React Native의 기본 API
  - 해당 URL을 **기기의 기본 브라우저(사파리, 크롬 등)**에서 엽니다.
- **특징:**
  - 앱을 떠나서 외부 브라우저로 이동
  - 사용자가 앱으로 돌아오려면 멀티태스킹 화면에서 다시 앱을 선택해야 함
  - 앱 내에서 웹페이지를 띄우는 것이 불가능
- **사용 예시:**
  - 정말로 외부 브라우저에서만 열어야 하는 경우

---

## 2. WebBrowser.openBrowserAsync (Expo 인앱 브라우저)

- **설명:**
  - Expo에서 제공하는 API
  - **앱 내부에 웹 브라우저(모달/오버레이 형태)**를 띄워서 사용자가 앱을 떠나지 않고 웹페이지를 볼 수 있게 함
- **특징:**
  - 앱 내에서 웹페이지를 띄우고, 닫으면 바로 앱으로 돌아올 수 있음
  - UX가 더 부드럽고, 이탈률이 줄어듦
  - iOS/Android 모두에서 일관된 경험 제공
- **사용 예시:**
  - SNS, 뉴스, 외부 링크 등 앱을 떠나지 않고 잠깐 웹페이지만 보고 싶을 때
  - Expo 기반 프로젝트에서 권장

---

## 3. WebView (react-native-webview)

- **설명:**
  - 앱 화면 내에 직접 웹페이지를 임베드(삽입)하는 컴포넌트
  - 완전히 앱의 일부처럼 웹페이지를 보여줌
- **특징:**
  - 네이티브와 웹 간의 상호작용(메시지 전달 등)이 가능
  - UI/UX를 완전히 커스터마이즈할 수 있음
  - 보안, 성능, 네이티브와의 통신 등 추가 관리 필요
- **사용 예시:**
  - 결제, 지도, 복잡한 웹앱 등 앱과 깊게 연동해야 할 때

---

## 4. 언제 어떤 방식을 써야 할까?

| 상황/목적                           | 권장 방식                          |
| ----------------------------------- | ---------------------------------- |
| 단순히 외부 웹페이지로 이동         | Linking.openURL                    |
| 앱 내에서 잠깐 웹페이지만 보고 싶음 | WebBrowser.openBrowserAsync (Expo) |
| 앱과 깊게 연동되는 웹앱/서비스      | WebView (react-native-webview)     |

---

## 5. 결론

- **Linking.openURL**: 외부 브라우저로 이동(앱을 떠남)
- **WebBrowser.openBrowserAsync**: 앱 내에서 웹페이지를 모달로 열고, 쉽게 닫고 돌아올 수 있음(앱을 떠나지 않음)
- **WebView**: 앱 화면 내에 웹페이지를 완전히 임베드(앱과 깊게 연동)

**따라서, 앱 내에서 외부 링크를 열 때는 WebBrowser 방식이 더 좋은 사용자 경험을 제공하며, 복잡한 웹 연동이 필요하면 WebView를 사용합니다!**

---

## 6. WebBrowser.openAuthSessionAsync (OAuth/외부 인증용 인앱 브라우저)

- **설명:**
  - OAuth 로그인(구글, 카카오, 네이버 등)이나 외부 인증이 필요한 경우,
    앱 내에서 인증 페이지를 띄우고 인증이 끝나면 다시 앱으로 안전하게 돌아오게 해주는 Expo의 인앱 브라우저 기능

### 주요 파라미터

| 파라미터    | 타입           | 설명                                                                   |
| ----------- | -------------- | ---------------------------------------------------------------------- |
| url         | string         | 인증(로그인) 페이지의 URL                                              |
| redirectUrl | null \| string | 인증 완료 후 앱으로 돌아올 때 사용할 딥링크 URL (옵션, 보통 자동 생성) |
| options     | object         | 추가 옵션 (대부분 기본값 사용)                                         |

### 플랫폼별 동작 방식

- **Android**: Custom Chrome Tabs 사용, AppState/Linking API로 앱 복귀
- **iOS**: Safari의 ASWebAuthenticationSession 사용, redirectUrl은 반드시 app.json의 expo.scheme 사용
- **Web**: window.open()으로 새 창(팝업/탭) 띄움, https 환경에서만 동작

### 동작 흐름

1. 사용자가 로그인 버튼을 누름
2. openAuthSessionAsync로 인증 페이지를 앱 내에서 띄움
3. 사용자가 인증을 완료하면, redirectUrl로 앱으로 돌아옴
4. Promise로 인증 결과(type: 'success', 'cancel', 'dismiss' 등)를 받음

### 반환값

- **Promise<WebBrowserAuthSessionResult>**
  - type: 'success' (성공), 'cancel' (사용자 취소), 'dismiss' (브라우저 닫힘) 등

### 주의사항

- **iOS**: redirectUrl은 반드시 app.json의 expo.scheme(예: myapp://)을 사용해야 함
- **Web**: https 환경에서만 동작, origin이 다르면 인증 완료 불가
- **Android**: 네이티브 구현이 없으면 브라우저 폴리필 사용

### 공식 문서

- [Expo WebBrowser 공식 문서](https://docs.expo.dev/versions/latest/sdk/webbrowser/)

### 결론

- openAuthSessionAsync는 인앱 브라우저에서 안전하게 인증(로그인 등)을 처리하고 인증이 끝나면 앱으로 돌아오게 해주는 OAuth/외부 인증에 최적화된 API입니다.
- 플랫폼별로 동작 방식이 다르니, redirectUrl, scheme, https 환경 등에 주의해야 합니다.

## 7. react-native-webview vs Expo WebBrowser 차이점

| 항목                     | react-native-webview                                                                 | Expo WebBrowser (openBrowserAsync)                                                 |
| ------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| **설치/의존성**          | 별도 설치 필요 (`npx expo install react-native-webview`)                             | Expo 프로젝트에 기본 포함                                                          |
| **동작 방식**            | 앱 화면 내에 네이티브 WebView 컴포넌트로 직접 임베드                                 | 앱 내에 모달/오버레이 형태로 외부 브라우저 띄움                                    |
| **UI/UX 커스터마이즈**   | 완전 자유 (내부 UI, JS-네이티브 통신 등)                                             | 브라우저 UI(뒤로가기, 닫기 등)만 제한적 커스터마이즈                               |
| **네이티브-웹 상호작용** | 가능 (postMessage, injectJavaScript 등)                                              | 불가 (단순 웹페이지 열기/닫기만 지원)                                              |
| **보안/세션 공유**       | 앱 내 세션, 쿠키 등 직접 관리                                                        | 외부 브라우저 세션 사용                                                            |
| **대표적 사용 예시**     | 결제, 지도, 복잡한 웹앱, 앱과 깊게 연동되는 기능                                     | 뉴스, 외부 링크, 간단한 웹페이지 보기                                              |
| **장점**                 | 강력한 커스터마이즈, 앱과 깊은 연동                                                  | 간편, 앱을 떠나지 않고 외부 페이지 보기                                            |
| **단점**                 | 성능/보안 관리 필요, 네이티브-웹 통신 이슈                                           | 커스터마이즈 제한, 네이티브 연동 불가                                              |
| **공식 문서**            | [react-native-webview 공식 문서](https://docs.expo.dev/versions/latest/sdk/webview/) | [Expo WebBrowser 공식 문서](https://docs.expo.dev/versions/latest/sdk/webbrowser/) |

### 요약

- **react-native-webview**는 앱 화면 내에 웹페이지를 완전히 임베드해서 앱과 깊게 연동할 때 사용합니다.
- **Expo WebBrowser**는 앱 내에서 외부 웹페이지를 간단히 띄우고, 닫으면 바로 앱으로 돌아오게 할 때 사용합니다.
- 목적과 필요에 따라 적절한 방식을 선택하세요.
